# FSHE 开发看板

GitHub Projects 的设计说明，用于规划 FSHE 的功能迭代与技术债清理。

- 看板地址：创建后填这里（`https://github.com/users/YG-O/projects/<编号>`）
- 适用范围：功能开发、技术债、构建发布、文档
- 更新节奏：每周过一遍「待办」，优先清 P0/P1

---

## 1. 字段设计

在 Project 的 **Settings → Custom fields** 中创建。

| 字段 | 类型 | 选项 | 说明 |
|------|------|------|------|
| `Status` | 内置单选 | 待办 · 进行中 · 待验证 · 已完成 | 卡片所在列 |
| `优先级` | 单选 | P0 紧急 · P1 高 · P2 中 · P3 低 | 见下方优先级定义 |
| `模块` | 单选 | 顶部栏 · 文件列表 · 回收站 · 主页 · 构建发布 · 文档 | 影响范围 |
| `版本` | 单选 | 1.0.2 · 1.1.0 · 待定 | 计划落地的版本 |
| `预估` | 数字 | 单位：小时 | 超过 8 小时要拆分 |

### 优先级定义

| 级别 | 含义 | 例子 |
|------|------|------|
| P0 | 阻断使用或数据风险 | 启动崩溃、误删无确认、大目录卡死 |
| P1 | 明显影响体验 / 发布必需 | 自动化构建、标签页状态串味 |
| P2 | 有价值但不紧急 | 浅色主题、地址栏补全 |
| P3 | 有空再做 | 清理无用代码、补充单测 |

## 2. 视图设计

| 视图 | 类型 | 配置 |
|------|------|------|
| 看板 | Board | 按 `Status` 分列；卡片显示 `优先级`、`版本`、`模块` |
| 排期 | Table | 按 `版本` 分组，按 `优先级` 排序 |
| 只看看 P0/P1 | Table | Filter：`优先级:P0,P1`；按 `模块` 分组 |

### 状态流转

```
待办 ──开始──► 进行中 ──提交──► 待验证 ──验证通过──► 已完成
  ▲              │                 │
  └────── 打回 ───┴─────────────────┘
```

**完成定义（DoD）**：能 `dotnet build` 通过 + 手动跑过改动路径 + 涉及打包的重新出过一次安装包。

## 4. 建卡方式

### 方式 A：网页手工建（无需额外权限）

1. 仓库页 → **Projects** → **New project** → 选 **Board**
2. 命名 `FSHE 开发看板`
3. Settings 里按第 1 节建字段，按第 2 节建视图
4. 逐条录入第 3 节的卡片

### 方式 B：先建 Issue 再拉进看板

```powershell
gh issue create --title "大目录异步加载 + 列表虚拟化" `
  --body "见 docs/PROJECT-BOARD.md 第 3 节" `
  --label "performance" --label "P0"
```

然后在 Project 页面点 **Link a project** / 在 Issue 右侧 **Projects** 里关联。

### 方式 C：命令行建项目（需要 `project` 权限）

```powershell
gh auth refresh -s project

gh project create --owner YG-O --title "FSHE 开发看板" --format json

# 之后的字段与批量建卡通过 GraphQL 完成：
gh api graphql -f query='query { viewer { login } }'
```

> `gh` 当前的 token 只有 `repo` / `workflow` / `gist` 权限，缺少 `project`，方式 C 需要先授权。

## 6. 维护约定

- 同一时间「进行中」**不超过 2 张**，避免上下文切换
- 卡片超过 8 小时预估必须拆成子任务
- 每完成一张，顺手更新 [Wiki 更新日志](https://github.com/YG-O/FSHE/wiki/%E6%9B%B4%E6%96%B0%E6%97%A5%E5%BF%97) 与 README 的功能列表
- 版本发布前，`版本` 字段筛选出目标版本，确认全部处于「已完成」
- 每月清理一次「待定」里超过 3 个月没动的卡片
